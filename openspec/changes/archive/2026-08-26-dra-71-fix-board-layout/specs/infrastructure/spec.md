# Infrastructure specification delta

## ADDED Requirements

### Requirement: Coupled DragnCards assets are refreshed from the checkout

The normal local startup paths SHALL treat `dragncards-mc-plugin`,
`dragncards-backend`, and `dragncards-frontend` as one coupled release unit. A
local start or restart through `scripts/docker.sh` or
`scripts/docker-infrastructure.sh` SHALL rebuild those images from the checked-out
submodule source unless `IMAGE_PULL_POLICY=always` explicitly selects registry
images, and SHALL force-recreate the three services before reporting startup
complete.

#### Scenario: Infrastructure start uses current submodules

- **WHEN** a developer changes the checked-out DragnCards or Marvel Champions
  plugin submodule commit and runs `scripts/docker-infrastructure.sh start`
- **THEN** the local frontend, backend, and plugin images SHALL be rebuilt from the
  current repository-root build context
- **AND** the plugin, backend, and frontend containers SHALL be recreated in that
  order of dependency before the helper reports success
- **AND** the backend SHALL mount the artifacts generated by that plugin image

#### Scenario: Full-stack start uses current submodules

- **WHEN** a developer runs the default `scripts/docker.sh start` with local images
- **THEN** the coupled DragnCards images SHALL be rebuilt and their containers SHALL
  be force-recreated
- **AND** a changed plugin image SHALL not leave an older backend container mounted
  against its artifact volume

#### Scenario: Registry start does not build local source

- **WHEN** a developer runs the registry workflow with `IMAGE_PULL_POLICY=always`
- **THEN** the helper SHALL skip local source builds
- **AND** it SHALL still recreate the coupled services so the pulled plugin image's
  artifacts are copied into the shared volume

### Requirement: Plugin artifact volume contents are replaced at the directory boundary

The `dragncards-mc-plugin` service SHALL replace only `/output/json` and
`/output/tsv` before copying the corresponding contents from `/plugin`. It SHALL
copy directory contents rather than copying the directory itself, so repeated runs
SHALL NOT leave stale root files or nested `json/json` or `tsv/tsv` directories.

#### Scenario: Repeated plugin refresh has one artifact tree

- **WHEN** the plugin service runs against an existing artifact volume
- **THEN** the volume SHALL contain the current image's JSON and TSV files directly
  below `/output/json` and `/output/tsv`
- **AND** files from an older plugin image SHALL not remain in those directories
- **AND** the service SHALL not remove any other named volume

### Requirement: Normal asset refresh preserves user game data

The coupled asset refresh SHALL not invoke a volume-removing Compose operation and
SHALL preserve the DragnCards database volume, Marvel engine asset/replay/runtime
volumes, and other persistent infrastructure volumes. Data removal SHALL remain an
explicit opt-in operation such as `scripts/docker.sh down-clean`.

#### Scenario: Start after an existing game

- **WHEN** a developer starts or restarts infrastructure after using DragnCards
- **THEN** the asset refresh MAY recreate the frontend, backend, and plugin
  containers
- **AND** the DragnCards database volume SHALL remain present with its existing game
  records
- **AND** the command SHALL not run `docker compose down -v`

### Requirement: Asset lifecycle regression diagnostics are available

The repository SHALL provide `scripts/test.sh infrastructure`, which SHALL verify
the rendered Compose coupling, shared plugin volume, checked-out-source build
contexts, artifact replacement command, and force-recreate lifecycle wiring. When a
backend container is running, it SHALL additionally compare the plugin image's
artifact manifest with the backend's mounted plugin volume and fail on a mismatch.

#### Scenario: Static lifecycle check

- **WHEN** `scripts/test.sh infrastructure` runs with no DragnCards stack available
- **THEN** it SHALL validate the Compose and script wiring
- **AND** it SHALL report that the live comparison was skipped rather than claiming
  that runtime artifacts were checked

#### Scenario: Live artifact check

- **WHEN** `scripts/test.sh infrastructure` finds a running DragnCards backend
- **THEN** it SHALL compare the plugin image and mounted-volume file manifests
- **AND** it SHALL fail with a mismatch diagnostic if the manifests differ
